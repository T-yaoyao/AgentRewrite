分析当前SQL结构：

```sql
SELECT NAME, DDEPTNO, C FROM (
  SELECT 'Charlie' AS NAME, DEPTNO AS DDEPTNO, COUNT(*) AS C FROM DEPT WHERE NAME = 'Charlie' GROUP BY DEPTNO 
  UNION ALL 
  SELECT 'Charlie' AS NAME, NULL AS DDEPTNO, COUNT(*) AS C FROM DEPT WHERE NAME = 'Charlie'
) AS u
```

**问题分析：**
1. 当前SQL是上一轮将GROUPING SETS展开为UNION ALL的结果，导致dept表被扫描两次
2. 两个分支都有常量 `'Charlie' AS NAME`，可以上提
3. 外层SELECT是简单的列转发，可以合并/移除
4. 两个分支共享相同的WHERE条件，但无法通过规则自动合并回CTE（CTE需要手动重写）

**可用规则分析：**
1. `UNION_PULL_UP_CONSTANTS` (UCT:1.100)：两个分支都有 `'Charlie' AS NAME` 常量列，可以上提到外层，减少UNION ALL分支的冗余计算
2. `PROJECT_MERGE` (UCT:0.620)：外层SELECT只是简单转发列，可以与内层合并消除冗余层
3. `FILTER_SET_OP_TRANSPOSE` (UCT:0.637)：外层无WHERE条件，不适用
4. `AGGREGATE_ANY_PULL_UP_CONSTANTS` (UCT:1.100)：第一个分支GROUP BY中name是常量，可以分离
5. `PROJECT_REMOVE` (UCT:0.587)：外层投影可以移除
6. `STRATEGY_CTE_DECOMPOSITION` (UCT:0.521)：将重复的WHERE条件提取为CTE，避免两次扫描

**核心瓶颈**：dept被扫描两次（各占42.6%成本）。最有效的方案是用CTE物化过滤结果，然后通过常量上提减少冗余。

选择规则：
1. `STRATEGY_CTE_DECOMPOSITION`：将重复的`DEPT WHERE NAME='Charlie'`提取为CTE
2. `UNION_PULL_UP_CONSTANTS`：上提两分支中的常量NAME列
3. `AGGREGATE_ANY_PULL_UP_CONSTANTS`：将GROUP BY中的常量列分离
4. `PROJECT_MERGE`：合并外层冗余投影
